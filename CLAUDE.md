# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

go-galaxy is a fast Ansible Galaxy collections and roles installer for CI, written in Go (module `github.com/greeddj/go-galaxy`). Collections come from Galaxy API servers, from git repositories, and from direct http(s) tarball URLs (url sources, pinned by sha256); roles come from the Galaxy v1 role API (then fetched by git at the tag it names), from git repositories, and from http(s) `.tar.gz` URLs, and install under `roles_path` (`--roles-path`, default `.roles`). One `install` handles both lists of one requirements file: `requirements.yml`, ansible's drop-in, or `galaxy.toml`, go-galaxy's own project file (a `[project]` table carrying the same two lists, a collection string carrying its constraint, inline tables for the mapping form, and a `[tool.go-galaxy]` table for the settings ansible.cfg has no key for - `lock_file`, `cache_dir`, `metrics_file`, `workers`, `download_workers`, an `s3` table, a `servers` array - with `${VAR}` expanded from the environment; a closed schema), picked by extension and discovered as `./galaxy.toml` over `./requirements.yml` when no flag names one; `file`, `dir` and local-path sources are refused. `vendor/` is git-ignored, not committed: it is regenerated locally by `just deps` and is absent in CI, so a local build resolves through it while CI downloads modules.

## Commands

Development is driven by the Justfile:

```bash
just test          # go test ./...
just check         # go vet, staticcheck, govulncheck, fieldalignment, actionlint (via go tool)
just lint          # golangci-lint run ./... (requires the exact pinned version, see below)
just fix           # go fix + fieldalignment -fix (autofixes struct field ordering)
just deps          # go mod tidy && go mod vendor - run after any dependency change
just build         # runs check+lint+test, then builds ./dist/go-galaxy and ./dist/go-galaxy-benchmark
```

Single test: `go test ./internal/galaxy/archive/ -run 'TestName'` (standard Go; tests live beside the code, in-package by default - the exception is the `internal/galaxy/collections` e2e suite, which is `package collections_test` so it drives the public API from outside; the `testpackage` linter is disabled so both styles are legal).

CI (`.github/workflows/ci.yml`) runs the same checks plus `go test -v -race -coverprofile=...`, so run tests with `-race` before considering concurrency work done.

Benchmarks: `testing/bench.sh` (needs `hyperfine`, a `.venv` with ansible-core, and `docker compose -f testing/docker-compose.yaml up -d minio-svc` for the s3-* scenarios). See README "Benchmarks".

## Things that fail the build in non-obvious ways

- **The test suite audits the source itself.** Several packages contain only tests that parse the repo with go/ast or enumerate files through git; `go test ./...` runs them all:
  - `internal/proseaudit`: no committed file may contain an em dash (U+2014) or en dash (U+2013) - hyphen-minus only, in prose, code, comments, and commit text. Also: a comment may cite a `foo_test.go:NNN` line only if a test failure could be attributed to that line, and may never cite a production file's line number - reference production code by identifier instead. And no comment block may run past three lines: a Go comment group, or a run of `#` lines in a `.sh`, `.yml`, `.yaml`, `Justfile`, `Dockerfile` or `.gitignore`; directive lines (`//go:`, `//nolint:`, `// #nosec`) do not count.
  - `internal/lockaudit`: every command that takes the cache backend's exclusive lock must run its work under the holder context that lock returned, judged via `cacheManager.LockLostError`. Checked over closed tables - adding or renaming such a command means updating the table, and a table entry naming a missing function fails rather than skips.
  - `internal/ciaudit`: gates the golangci-lint version literal, which is spelled in both the Justfile (`GOLANGCI_LINT_VERSION`) and `.github/workflows/ci.yml` and must match. Bump both in one commit. The workflow files themselves are checked by `go tool actionlint` in `just check`, not here.
  - `internal/galaxy/store` has a dirty-flag audit (every write-locked `*Store` method must set the dirty flag; a new bucket also needs `helpers.StoreSnapshotSchemaVersion` bumped, drop-and-rebuild), `internal/galaxy/archive` gates its probe's decompressor path, `internal/gzipstream` has a monopoly gate: no package outside it may import klauspost/pgzip for reading, `internal/galaxy/projectfile` has the same gate for github.com/BurntSushi/toml (no non-test file outside it may import it, resolved by import path), and `internal/cache/s3` reads its own source so that every package-level variable named `err` or `Err` then an upper-case letter needs a row in `sentinelClassCases` pinning the one cache-backend class it carries, or none.
- **golangci-lint runs with `default: all`** and a short disable list (`.golangci.yml`). depguard has an explicit import allow-list - importing a new module requires adding it there, plus `just deps` to update go.mod/vendor.
- **fieldalignment is enforced** (`just check` and CI), so struct field order matters; `just fix` reorders automatically.

## Architecture

The layering is: `cmd/go-galaxy` is wiring, `internal/galaxy/*` is the work, `internal/cache/*` is persistence behind a seam, and a few leaf packages hold cross-cutting concerns.

- `cmd/go-galaxy`: main.go (signal handling, exit-code decision via `exitcode`), `cliflags` (flag declarations), `commands` (urfave/cli command tree: install, cleanup, lock, warm, hash, tree, explain, outdated). install/cleanup/lock/warm/outdated share `runCollectionCommand`, which builds the `*config.Config`, the progress printer, and the `*infra.Infra`. hash/tree/explain work straight from files on disk, resolving the lockfile through `lockfilePath` (lockpath.go: `--lock-file` when set, else a galaxy.toml's `lock_file` via `projectfile.LoadSettings`, else `galaxy.lock` beside the requirements file - so even hash exits 2 on a galaxy.toml that does not load). runner.go prints `Infra.DebugConfigSources` under `--verbose`.
- `cmd/go-galaxy-benchmark`: a second binary, and the only package in the tree that is not the product. It times `ansible-galaxy collection install` against `go-galaxy install` over `testing/requirements-<size>.yml`, writes every run's wall clock to a JSON report, and renders that report as a `text/tabwriter` table or an SVG bar chart. Two entry points: `run` measures and prints, `show` re-renders a report already on disk and touches neither the network nor the measured binaries. Its measurement rules are deliberate: closed stdin on every measured command, so a tool that decides to prompt cannot be mistaken for one that hung; a failing run recorded and left out of the mean rather than ending the series; one cache and one temporary tree per tool, so neither can warm the other and both do their temporary work on the same filesystem. `.goreleaser.yml` builds `./cmd/go-galaxy/main.go` alone, so this binary is never published.
- `action.yml` at the root: the repository's own composite GitHub Action, and the one artifact here `go test ./...` cannot reach - what it does is download a published release and run it, and neither half exists inside the module. It resolves the release from `github.action_ref` (an exact `@v1.2.0` names one, `@v1` and a branch do not and fall back to latest), checks the binary against the release's `checksums.txt`, refuses a runner the release has no build for by name, and keys `actions/cache` on the runner platform, the installed release and `go-galaxy hash` - the release is in the key because a binary handed a cache snapshot written by a newer one refuses it rather than rebuilding. Every flag it passes is added only when its input is set, so an input left alone leaves the matching `GO_GALAXY_*` variable in charge instead of being silently outranked. Every `run` step spells `shell:` because a composite action inherits no `defaults.run` from its caller, and every input reaches a script through the environment rather than through `${{ }}` inside it. `.github/workflows/action.yml` is its only test and runs on a change to either file; `.github/workflows/release.yml` moves the lightweight `v1` tag so `@v1` resolves, which is why the Justfile's `git describe` carries `--match`.
- `internal/galaxy/collections`: the resolve-download-verify-extract-record pipeline behind install/warm/lock/outdated. Cache access funnels through `withBackend` (open, take exclusive lock, run under the holder context). `outdated` is the exception that opens no backend at all: its current side comes from the lockfile, or - with no lockfile - from the installed collections tree (`outdated_installed.go`, driven from each install's `<ns>.<name>-<version>.info/GALAXY.yml` sidecar and cross-checked against the collection's own MANIFEST.json, so a sidecar an upgrade left behind contributes nothing). A git requirement is expanded by `expandGitRoots` (git_discovery.go) before the solver runs: its repository is fetched, its collections built and committed to the artifact store, and each becomes an exact-pin root whose `Source` is the locator `git+<url>#<subdir>@<commit>` - the one string every downstream consumer (artifact key, installed record, snapshot, cleanup) keys on. A url requirement takes the same road one step simpler (`expandURLRoots`, url_discovery.go): the tarball is downloaded over the dedicated url client (`Infra.URLHTTP`), its identity and dependencies read from its MANIFEST.json (`collectionbuild.ParseManifestInfo`), the artifact committed under the locator `url+<url>#sha256:<hex>`, the pin recorded in the `url_pins` bucket keyed by the URL alone, and a `version:` in the entry is asserted against the manifest on both the fresh and the replay path. `internal/galaxy/urlsource` is the url grammar (URL, credential-binding prefix, locator), gitsource's sibling with no transport of its own.
- Roles, in the same package, in the `role_*.go` files: `resolveRoles` (role_resolve.go) walks the `roles:` entries and their `meta/main.yml` + `meta/requirements.yml` dependencies breadth-first, first-wins by install name, capped at `helpers.RoleGraphMaxRoles`; a Galaxy role is mapped to a GitHub repository and tag through `internal/galaxy/galaxyv1` (role_galaxy.go) and then takes the git path exactly as an scm role does; the artifact is keyed `ArtifactKey(<git+<url>#@<commit>>, RoleArtifactFilename(name, version))` in the git artifact store. `installRoles` (role_install.go) extracts through the extracted store into `<roles_path>/<name>/` under an `os.Root` at roles_path and writes ansible's `meta/.galaxy_install_info`; the extract marker is what marks a directory as this tool's, a directory with neither the marker nor `.galaxy_install_info` is refused (`ErrRoleDirectoryForeign`). role_lock.go renders and verifies lockfile role entries (schema 3, `lockfile.RoleEntry`, pinned by commit, no sha256); role_outdated.go, role_dryrun.go and `warmRoles` (warm_command.go) are the role halves of those commands. A url role (role_url.go) is downloaded like a url collection, normalized through `internal/galaxy/tartree` (the one place a foreign tar.gz becomes a `treearchive.Source`: the role root is the archive root or the single top-level directory carrying meta/main.yml, anything else is refused) and repacked by rolebuild; its pin is the origin bytes' sha256, its locator `url+<url>#sha256:<hex>`, its default version label the sha's first 12 hex digits, and its lockfile entry (schema 4) carries a real sha256 where a git role's is refused. The snapshot carries two role buckets, `installed_roles` (by install name) and `role_pins` (git pin by `url\nref\n` - the git pin key with an empty subdir - Galaxy pin by `galaxy\nname\nrequested-version`, url pin by `url\n<url>`); the project registry records `roles_path`, and `internal/galaxy/cleanup/roles.go` scans only a recorded roles path, counts only directories carrying the extract marker, and keeps what a project's `roles:` roots reach through recorded deps.
- Git sources, three leaf packages: `internal/galaxy/gitsource` is the grammar (URL, ref, subdir, locator, credential matching) and the `Client` interface, and imports no go-git; `internal/galaxy/gitfetch` is the only production importer of go-git (advertise once, fetch by hash through the upload-pack session into a byte-capped on-disk store, read the tree without a checkout) and implements `Client`; `internal/galaxy/treearchive` is the only production tar writer (two-pass walk under the archive caps, symlink policy, deterministic `tar.gz`) and `internal/galaxy/collectionbuild` drives it with what makes the result a collection: the ignore rules, the `MANIFEST.json`/`FILES.json` lead documents that `ansible-galaxy collection build` would produce, and the identity read from `galaxy.yml`. `internal/galaxy/rolebuild` is collectionbuild's role counterpart: it reads `meta/main.yml` (else `meta/main.yaml`; both is refused) and `meta/requirements.yml` for dependencies and drives treearchive into a tar.gz with no lead documents and every entry at the top level. `internal/galaxy/galaxyv1` is the Galaxy v1 role API client (lookup by owner and name, paginated versions within the server's origin, ansible's LooseVersion selection), which validates every field of a record and composes the GitHub URL rather than copying one. `internal/testing/faketree` is the in-memory `treearchive.Source` every builder test and the install pipeline's git double build from. `gitsource.Client` has `Advertise`, `Acquire` (collections) and `AcquireRole` (the role at the repository root); gitfetch implements all three. `gitfetch.New` uninstalls go-git's `file` and `git` transports and switches off its `~/.ssh/config` reader, once per process; a test pins both.
- **Cache seam**: `internal/galaxy/cache` declares the interfaces (`Backend` for state/locking, `ArtifactStore` for tarballs) plus decorators and the cache-policy-aware JSON fetch. `internal/cache` is the only factory choosing a concrete backend: `internal/cache/local` (BoltDB snapshot + JSON registry + flock) or `internal/cache/s3` (gzipped-JSON objects, hand-rolled SigV4 signing - no AWS SDK - and a distributed lock on conditional writes with a heartbeat).
- `internal/galaxy/projectfile` decodes `galaxy.toml` (the only importer of github.com/BurntSushi/toml) into the same `any` tree yaml gives and holds it to the closed `[project]` schema; a TOML parse error is rendered as line and last key only, never the library's message. `requirements.Load` dispatches by extension (`projectfile.IsTOMLPath`): `.toml` to `requirements.ParseTOML`, which reshapes each entry (a collection string split into name and constraint, checked with semver at load as `ErrInvalidCollectionConstraint`; inline tables held to closed key sets) and feeds `parseRaw`, so both formats share one validation order; anything else to `Parse`. `config.RequirementsPath` is the one place the default path is decided: a set flag or variable verbatim, else `./galaxy.toml` when it is a regular file (with a warning when `./requirements.yml` is one too), else the relative `requirements.yml` without a Stat; `newConfigFromCLI` queues its warning on `Config.Warnings`, and hash/tree/explain call it themselves and print through `progress.Warnf`. The `[tool.go-galaxy]` table decodes into `projectfile.Settings` (`S3Settings`, `[]ServerSetting`; `Decode` checks the schema and expands nothing, so a `[project]` reader never needs the environment) and is read through `LoadSettings(path)`: an absent file is zero `Settings`, every `${VAR}` under the table (`\$\{[A-Za-z_][A-Za-z0-9_]*\}`; a bare `$VAR` and anything under `[project]` stay literal) is expanded from the environment with every unset name collected and reported once, sorted, as `helpers.ErrProjectFileEnvUnset` (exit 2, never a value), a token that held a reference is marked `TokenExpanded`, and a relative `lock_file`, `cache_dir` or `metrics_file` is joined under the file's directory. `config.BuildCollectionConfig` loads it first (`newConfigWithProject`, ahead of `applyTimeout`, so a broken galaxy.toml is the first error a run reports) and layers each key as flag or variable when set > `[tool.go-galaxy]` > ansible.cfg (two keys have that layer: `cache_dir`, outranked by value, and the servers, whose `[galaxy] server_list` and `[galaxy_server.<id>]` sections are read only when the table has no entries) > the flag's default, recording every key taken in `Config.ProjectSettingsUsed` for `Infra.DebugConfigSources`; `[[tool.go-galaxy.servers]]` replaces the `[galaxy_server.*]` sections outright (never merged; an exported `ANSIBLE_GALAXY_SERVER_LIST`, even empty, still supplies the id list instead) and goes through the same `buildServer` and `ANSIBLE_GALAXY_SERVER_<ID>_*` overrides; the S3 secrets and a server token become `config.Secret`, and the `projectSettings` value (a type alias of `projectfile.Settings`) is passed by value and kept nowhere. `config.checkTokenPairing` covers both files: a token from `--token`, `ANSIBLE_GALAXY_SERVER_<ID>_TOKEN` or a toml `${VAR}` is the operator's and is refused beside a file-sourced url (`helpers.ErrTokenDestinationFromFile`) or a file-disabled TLS check (`helpers.ErrTokenTLSPolicyFromFile`), while a literal token in either file is that file's own and exempt. `cleanup` mounts the requirements flag (and so runs discovery) only so a galaxy.toml can name the cache_dir, S3 settings and servers of the cache to clean; it still reloads each project's recorded path for roots.
- `internal/galaxy/helpers`: bottom of the import graph. Sentinel errors (matched with `errors.Is` across layers), size caps and tuning constants, and validation predicates (`IsPathElement`, `IsCollectionName`, `IsSHA256Hex`, `IsExactVersion`, and for roles `IsRoleName`, `IsRoleInstallName`, `IsRoleVersion` - deliberately not derived from the collection alphabet, since real role names carry hyphens, upper-case letters and leading digits). A value's shape is judged by one rule at the boundary it enters through.
- `internal/galaxy/infra`: per-run DI container (printer, shared Galaxy HTTP client, the url-source client `URLHTTP`, the git client and revealed git credentials, clock, metrics counters, test-only deadline overrides). Extend Infra rather than adding a global or widening signatures.
- `internal/galaxy/solver`: pure, deterministic PubGrub-style version solver; all metadata comes through its Provider seam, no I/O.
- `internal/galaxy/lockfile`: pins every transitive collection to exact version + SHA256 + the `download_url` its server named, or, for a git source, to its commit (`type: git`, `ref`, `commit`, `subdir`, no sha256), and every role (a `roles:` list of `RoleEntry`: name, `type: galaxy|git|url`, version as asked, galaxy name, source, repository, ref, commit, deps, and a sha256 only on a url role); the highest feature present picks the schema - a Galaxy entry 5 (its `download_url` is required, so a Galaxy entry in an older file is refused until `lock` rewrites it), a url entry 4, a role 3, a git entry 2, none of them 1. Save and Hash share one two-space-indent encoder whose bytes `TestSaveEmitsCanonicalBytes` pins, since `go-galaxy hash` is their SHA256. With a lockfile, install resolves nothing and asks no Galaxy API: a Galaxy cache miss fetches the locked `download_url` alone (a verifying run still reads the version metadata its signatures ride on, via `resolveFromLockfile`'s `lockedURLs`), and a cache miss on a role fetches its pinned commit and refuses a remote that serves another (`ErrRoleArtifactIdentityMismatch`).
- Output: `internal/galaxy/output` declares the `Printer` interface (tiers behave differently under --quiet/--verbose); `internal/progress` implements it (spinner only on a TTY). `internal/safeout` strips terminal control sequences from any text of external origin before it is printed - use it for anything derived from network responses, archives, or paths.
- `internal/gzipstream`: the single place a gzip reader is opened over untrusted bytes (context observed on the compressed side, zero-byte members refused).
- `internal/testing/fakegalaxy`: in-memory Galaxy v3 API double with fault injection, request counting, and auth capture - use it for any test touching HTTP paths; nothing in tests hits a real network. It serves the v1 role routes (`roles/?owner__username=&name=`, paginated `roles/<id>/versions/`) once `AddRole` has registered a role, and answers 404 for them before that, which is how "a server without v1" is modeled. `internal/testing/fakegit` is its sibling for a git remote: an in-process smart-HTTP server and ssh listener (plus agent and known_hosts fixtures) over in-memory repositories with deterministic commits, with `AddRole` writing a minimal role tree at a repository root; the collections suite uses an in-memory `gitsource.Client` double instead (git_fake_client_test.go, git_fake_roles_test.go) and leaves the transport to `gitfetch`'s own tests. The role pipeline's end-to-end coverage is roles_e2e_test.go.

## Security posture (deliberate boundaries, keep them)

Untrusted input is validated where it enters (`requirements` parsing, `manifest` reading, `archive` extraction with sentinel-named refusals and path/symlink/size caps). Filesystem writes under the cache go through `os.Root` so nothing beneath it can redirect a write or delete outside the configured tree. Credentials are `Secret` values that redact on every serialization path (`config`). `manifest` and `signature` are read-only by design. A server URL or relaxed TLS setting from ansible.cfg or galaxy.toml is never paired with a token from another source (a galaxy.toml token spelled as `${VAR}` is another source: it belongs to whoever set the variable, not to the file). A git repository URL is repository content: it may carry no credential, its path is held to a conservative alphabet, and the credential it gets is bound to a host through the environment (`GO_GALAXY_GIT_*`) and matched by origin and path prefix; git traffic runs on its own HTTP client (`fetch.NewGit`) that carries no Galaxy token and refuses cross-origin redirects, an ssh host key must be in known_hosts, no process is ever executed, and a fetched tree is validated entry by entry before anything is built from it. A url source is judged the same way: the URL may carry no credential and no fragment, its path is held to a conservative alphabet and may carry no dot segment (a server resolves those while the credential match reads the path as written; the one admitted empty segment is the `//` of a canonically spelled embedded upstream URL - the caching-proxy shape `http://front/<upstream-url>` - which both the grammar and the credential match recognize by the same rule), the Bearer token it may get is bound through `GO_GALAXY_URL_*` and re-decided on every redirect hop (a hop into an unbound origin - the GitHub release shape - carries no Authorization header at all, and an https-to-http downgrade hop is refused outright), url traffic runs on its own client (`fetch.NewURLDownload`) that holds no Galaxy token and no relaxed TLS for any origin, and the sha256 pin in the locator is enforced on every fresh download, cache hit, refetch and frozen install. A lockfile's `download_url` is repository content as well: canonical http(s) with no userinfo, query or fragment, and held to its server's own artifact - that server's origin, a path ending in `<ns>-<name>-<version>.tar.gz` - by `lock` and, before any request, by `--frozen` (`checkLockedDownloadURLs`), because the bytes it fetches land in the cache slot every later install of that version reads; a refetch after a pin failure keeps the cached copy, so a wrong pin cannot empty that slot. A role adds the same boundaries one level over: role writes go through an `os.Root` at roles_path with the install name validated before it is joined, a Galaxy v1 record's `github_user`/`github_repo` are held to the GitHub name alphabet and composed into an `https://github.com` URL (`download_url` is never read, a pagination link is followed only within the server's origin), the Galaxy token never reaches github.com because the repository fetch runs on the credential-free git client, and cleanup removes only a directory carrying this tool's extract marker under a recorded roles path. Don't casually loosen any of these; `docs/security.md` and `docs/architecture.md` state the boundary each package owns.

## Conventions

- Every comment block is at most three lines, package doc comments and tests included; `internal/proseaudit` fails the build otherwise. Reasoning that needs more goes to `docs/`: how a package works in `docs/architecture.md`, the boundary it enforces in `docs/security.md`. Keep the comment and the doc true after your change.
- Comments state constraints and reasons, not narration; match that register.
- Only hyphen-minus in everything committed (enforced by test, see above).
